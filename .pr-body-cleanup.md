Small follow-up cleanup from the workspace-start-boundary fix (see monorepo Spec note, Final verification section).

## Changes

Removes the legacy `commits[commits.length - 1].hash` boundary heuristic from `files-git-seeder.ts` (line 81) and makes the seeder consistent with the production wire shape.

### files-git-seeder.ts
- Changed from calling `commits()` and deriving `boundarySha` heuristically
- Now calls `commitsWithBoundary()` directly and uses `envelope.boundarySha`
- Consistent with production path in lifecycle-read-service.ts

## Context

The old heuristic was dead code:
- The seeder runs against `LiveAppClient`
- `LiveAppClient.git.commits()` delegates to `commitsWithBoundary()` (per PR #137)
- So even the old path would receive the daemon's `boundarySha` indirectly via the envelope

Production paths (lifecycle-read-service.ts, live-git-client.ts) are already correct per PR #137 and were not touched.

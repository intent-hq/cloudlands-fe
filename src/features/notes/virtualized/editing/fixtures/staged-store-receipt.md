# Staged Store receipt replay

`staged-store-receipt.capture.txt` preserves the original captured JSON bytes from
`intent-store`'s registered
`staged_receipt_fe_budget_transcript_retains_every_response` test in
`crates/intent-store/src/tests/note_pages/staged_receipt_fe_capture.rs`.
The capture SHA-256 is
`0b9927c182f736f73ca9ac4450602cba168292f2f7d2b92ea2ee516df0ba300a`.
It was emitted by Store run `ff2d81a3-a765-410d-ae3d-0af3fc3b5be3`
(script `c313933d-59dd-4631-a140-7b59c7444617`) on base
`a8386c9868f2e110d97e1fea9e0b4631b0a3ee3c`. The producing test source SHA-256
is `a8f2465aa76e97168a54083923c2a57cf5e5d4ce0adf2002d1fcf8feccf5333b`.
The producer is published in
[intentd commit c0f1de67](https://github.com/intent-hq/intentd/blob/c0f1de673d18e616d2a2232a2f99df12b84f8116/crates/intent-store/src/tests/note_pages/staged_receipt_fe_capture.rs).
The text extension keeps formatting tools from rewriting this captured artifact.

The Store creates `ab😀cd`, stages the three composed dirty records in native
history groups 1 and 3, commits `aBBB😀CdZ`, and reads the resulting mapping,
effects, inverse, inverse-text, and full metadata-tree provenance responses.
The newer group's insertion at source position 8 is beyond the original base
length 6. It distinguishes group-relative provenance from global-base positions.
The begin, upload, seal, and commit inputs retain their original identities and
hashes. The capture includes an owned empty inverse replacement.

The frontend test imports those bytes unchanged, verifies their checksum and
canonical request digests, and compares the captured dirty records with groups
independently generated by the native edit core. It replays each response through
the actual Live client, receipt decoder, semantic consumer, saga, and reducer.
Only the internal Store query's field spelling is translated into public request
selectors: nested scope becomes the four scope fields and `reference` becomes
`ref`. Budgets, cursors, offsets, receipt identity, and response data stay exact.
Duplicate or extra reads fail. The test clock is after the recorded staging
expiry and within the original receipt lifetime; the stored deadlines are not
extended. These small pages have no continuation cursors or external scalar
`valueRef` fragments; those traversal cases retain their separate reader tests.

The positive control checks preserved native history and undo/redo from a fresh
controlled paragraph authority at the saved revision. Separate negative controls
alter a valid group-relative provenance range or remove the older inverse group;
reconciliation remains required and retained work stays intact.

This is Store-output-to-frontend integration evidence. Native paragraph authority
is a controlled fixture. It does not execute a live upload, transport, or daemon
authorization session, prove arbitrary canonical effects or later-edit rebasing,
establish full RPC predecode accounting, or activate normal routes or capabilities.

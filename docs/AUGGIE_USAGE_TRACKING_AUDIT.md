# Auggie Agent Usage Tracking Audit

> ⚠️ This audit was conducted on 2026-03-17. The recommended changes were never implemented. This document is preserved for reference but may not reflect current code.

## Executive Summary

This document audits the current state of usage tracking for Auggie agents within the WorkSpaces app and provides recommendations for enabling usage benchmarking via BigQuery.

**Key Finding**: The WorkSpaces app spawns the `auggie` CLI process which handles all LLM API calls. Usage tracking must happen at both the WorkSpaces app level (for auxiliary API calls) and the auggie CLI level (for LLM usage).

## Current Architecture

### How Auggie Works in WorkSpaces

```
WorkSpaces App (Electron)
    ↓ spawns
Auggie CLI Process (--acp mode)
    ↓ makes API calls
Augment Backend API
    ↓ logs to
BigQuery
```

### Session/ID Management

The app uses multiple identifier types:

1. **`agentId`** - Primary identifier (format: `agent-{uuid}`)
   - Used for UI routing and state management
   - Generated by `UnifiedIdService.generateAgentId()`

2. **`sessionId`** - Internal ACP session ID (UUID format)
   - Created by auggie CLI when session starts
   - Different from agentId

3. **`frontendSessionId`** - Maps to agentId for stream routing
   - Used to route streaming responses to correct UI component

4. **`workspaceId`** - Workspace identifier (format: `adjective-noun-xxxx`)
   - Identifies which workspace the agent belongs to

### Current Agent Context Passing

When spawning auggie, the app passes these environment variables:

```typescript
// From: src/features/agent/main/agent-providers/acp-provider.ts
env: {
  AGENT_ID: this.config.agentId || 'agent',
  AGENT_NAME: this.config.name || 'Agent',
  AGENT_SESSION_ID: this.sessionId || '',
  AGENT_TURN_NUMBER: turnNumber?.toString(),
  // ... other env vars
}
```

These are then used by MCP tools via the HTTP bridge to track provenance.

## Current API Communication

### AugmentApiClient (Auxiliary Services)

Location: `src/shared/augment-api/augment-api.client.ts`

**Current Headers**:
```typescript
headers: {
  'Content-Type': 'application/json',
  Authorization: `Bearer ${this.session.accessToken}`,
}
```

**Missing**:
- ❌ User-Agent header
- ❌ Conversation ID / Session ID
- ❌ Request source identifier

**Used For**:
- GitHub API operations (PRs, issues)
- Linear integration
- Remote tool execution
- NOT used for LLM API calls (handled by auggie CLI)

### Auggie CLI Communication

The auggie CLI is spawned as a child process and handles all LLM API calls internally. The WorkSpaces app communicates with it via:
- **stdin/stdout**: ACP protocol messages
- **Environment variables**: Agent context (ID, name, session)

**Critical Gap**: We don't control what headers auggie sends to the backend API.

## BigQuery Usage Tracking (Per Team)

According to the team:

1. **Current Capabilities**:
   - Enterprise credits dashboard queries BigQuery
   - Can aggregate by user (no further granularity currently)

2. **Available Fields**:
   - **"request source"**: Derived from User-Agent header
     - Can differentiate different clients (VSCode, CLI, WorkSpaces)
   - **"conversation id"**: Can be passed by client
     - Allows aggregating usage by agent thread/session

3. **Limitation**: Current endpoint only breaks down by user, but raw BigQuery data has more granularity

## Recommendations

### 1. Enhance AugmentApiClient (WorkSpaces App)

**Priority**: Medium (only affects auxiliary API calls, not LLM usage)

Add User-Agent and conversation tracking to auxiliary API calls:

```typescript
// In src/shared/augment-api/augment-api.client.ts
private async callEndpoint<T>(endpoint: string, request: object = {}): Promise<T> {
  const response = await fetch(url, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${this.session.accessToken}`,
      'User-Agent': `Augment-WorkSpaces/${app.getVersion()}`,
      'X-Conversation-Id': this.currentAgentId || 'unknown', // Pass when available
      'X-Request-Id': uuidv4(), // Unique per request
    },
    body: JSON.stringify(request),
  });
}
```

**Benefits**:
- Tracks GitHub/Linear API usage from WorkSpaces
- Differentiates WorkSpaces from VSCode/CLI in BigQuery
- Minimal implementation effort

## Conclusion

**For WorkSpaces App**: We can add User-Agent and conversation ID to auxiliary API calls (GitHub, Linear, etc.) but this won't track the main LLM usage.

**For LLM Usage Tracking**: The critical work needs to happen at the auggie CLI level. The WorkSpaces app already passes agent context via environment variables, but we need to verify that auggie actually uses this information when making backend API calls.

**Recommended Next Steps**:
1. Implement User-Agent in AugmentApiClient (quick win)
2. Coordinate with auggie CLI team to verify/enhance usage tracking
3. Work with backend team to expose conversation-level usage data in BigQuery

Wave 2 of the workspace-start-boundary fix. Implements FE consumption of the BE-provided boundary SHA and wires the "show previous" toggle.

## Changes

### live-git-client.ts
- `commits()`: Added optional `includeOlder` parameter that forwards to daemon
- `commitsWithBoundary()`: New method returning full envelope `{ commits, boundarySha, nextToken }`
- Both methods map daemon `file-tracking.loadCommits` response (PROTOCOL §5.19)

### app-client.ts
- Updated `GitClient` interface with new signatures and documentation

### lifecycle-read-service.ts
- `refreshChanges()`: Now uses `commitsWithBoundary()` to store daemon's `boundarySha` directly (replaces `commits[commits.length-1].hash` heuristic)
- `loadOlderCommits()`: New handler that calls daemon with `includeOlder: true` and dispatches to `olderCommits`
- Wired up `loadOlderCommitsRequested` action in middleware switch

### Tests
- Added 6 new test cases in `live-git-client.test.ts`:
  - commits with includeOlder parameter
  - commitsWithBoundary returns full envelope
  - commitsWithBoundary handles null boundarySha
  - commitsWithBoundary forwards includeOlder
  - commitsWithBoundary degrades gracefully on error
- All 51 tests passing

## Wire Shape (from Task 1 / PR #235)

Request:
```json
{
  "workspaceId": "workspace-abc",
  "includeOlder": false  // optional, default false
}
```

Result:
```json
{
  "commits": [...],
  "boundarySha": "def456...",  // workspace boundary commit SHA, or null
  "nextToken": "..."            // pagination token, or null
}
```

When `includeOlder` is false (default), returns commits in the `boundary..HEAD` range (workspace-owned commits only). When true, returns commits before and including the boundary (for "show previous" functionality).

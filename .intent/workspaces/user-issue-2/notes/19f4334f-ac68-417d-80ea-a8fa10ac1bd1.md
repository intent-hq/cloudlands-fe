# Fix attached note/artifact navigation

Implement the minimal fix so attached notes/artifacts render and navigate with a real persisted note id and correct workspace context, rather than a title slug or current-workspace-only fallback when the target is external.

## Scope
In scope: the smallest set of parser/link/navigation files identified by the diagnosis task. Preserve existing behavior for normal markdown links, `intent://local/note/spec`, `intent://local/task/{id}`, file mentions, image/file downloads, and cross-workspace links. Do not introduce Svelte stores; follow Redux selector lifecycle rules for any event-handler state reads.

## Inputs
Depends on the diagnosis task findings. Use `noteUrl(noteId, workspaceId?)` and `noteLink(text, noteId, workspaceId?)` as the canonical URL builders when a note is known. If the artifact is not a note, route it through the existing artifact/file/resource path instead of manufacturing a note id.

## Definition of Done
Clicking an attached note/artifact whose visible title is `PR 17 Safety Review` no longer attempts to open `pr-17-safety-review` unless that is the actual persisted note id. Created-note results use the actual returned id. Cross-workspace note links include the workspace id when available. Missing notes still show a clear Not Found toast.

## Verification
Add or update unit/component tests for the fixed path. At minimum, include a regression fixture where visible text is `PR 17 Safety Review` but the note id differs from `pr-17-safety-review`, and assert the navigation target uses the actual id.

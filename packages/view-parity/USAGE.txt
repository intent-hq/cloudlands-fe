Independent Svelte / React browser checks

Run from the repository root with corepack pnpm. The foundation workspace install
owns dependencies and the root lockfile. This package never launches a daemon,
intercepts a request, fabricates a response, or updates screenshot baselines.

Coverage scope: component catalog journeys only, never full application coverage.
Named-scene comparisons and source catalog fixture comparisons are separate case
kinds. The manifest lists every checked source and explicitly records gaps;
migration-inventory.json owns the full migration denominator.

Core includes native form validation, pending/rejected submission protection,
Enter/mod-Enter/multiline and caller keyboard policies, form reset/dirty/errors,
autosave debounce/blur/save shortcut and external updates with focused draft
retention, collection keyboard/typeahead/selection and nested controls,
confirmation/prompt promises, and basic control journeys. Extended adds failed-save
retry, queued/rejected confirmation callbacks, dynamic and virtualized collection
navigation, dismissal/focus edges, takeover scroll ownership, slider pointer and
inline editing, and disabled/invalid paths. Every case uses production components
and handlers. New catalog journeys exercise controlled question navigation and
validation, composer send/queue/suggestion/history behavior, picker filtering and
multi-selection, Select wrapper lookup, real sidebar persistence, editable names,
portals, rich tooltip forwarding, scroll thumbs and catalog keyboard navigation.
Widget interaction hosts have no source appearance fixture unless explicitly mapped.
Native requestSubmit calls exercise the actual pending form handler;
no dependency, response, clock, or handler is replaced.

Test discovery is not a browser pass. New example controls must be committed and
reported ready by their owner before acceptance runs. Report every failing or
unrun case separately. Remaining control edges and real-daemon/Electron journeys
are listed as gaps in the manifest.

Catalog and functional fixture startup allow 15 seconds for the real renderer to mount,
matching preview readiness. This covers a cold dev-server import crawl; ordinary
behavior assertions retain their five-second budget. Missing or partial fixtures
still fail, and no retry is enabled.

  corepack pnpm --filter @intent/view-parity manifest:check
  corepack pnpm --filter @intent/view-parity browsers:install
  corepack pnpm --filter @intent/view-parity compare --list
  corepack pnpm --filter @intent/view-parity test:core --list

Use two independently running apps. In a clean Svelte checkout, install that
checkout's locked dependencies and run corepack pnpm run dev:ui. In the candidate
checkout run corepack pnpm run dev:react (default port 5174). Read the actual
reference port from its startup output; do not assume a stale server is current.

  corepack pnpm --filter @intent/view-parity compare \
    --reference-url http://127.0.0.1:5173 \
    --reference-root /absolute/path/to/clean-svelte-checkout \
    --candidate-url http://127.0.0.1:5174

  corepack pnpm --filter @intent/view-parity test:core \
    --candidate-url http://127.0.0.1:5174

  corepack pnpm --filter @intent/view-parity test:extended \
    --candidate-url http://127.0.0.1:5174

Flags also accept environment variables:
  --reference-url   PARITY_REFERENCE_URL
  --candidate-url   PARITY_CANDIDATE_URL
  --reference-root  PARITY_REFERENCE_ROOT
  --candidate-root  PARITY_CANDIDATE_ROOT
  --artifacts       PARITY_ARTIFACTS
  --case            PARITY_CASE (comma-separated exact case IDs; parity only)
  --grep            PARITY_GREP (test title filter for focused reruns)

--list enumerates tests without connecting to an app. It is not a test pass.
Unknown cases and empty test projects fail. Core never runs parity or extended.
Extended is optional coverage for additional keyboard/dismissal paths, not a
replacement for core. Playwright retries are disabled and .only is forbidden.

Evidence and comparison

Every run gets a fresh directory under .demo-artifacts/view-parity (gitignored).
--artifacts can choose a parent under the owning workspace's
.demo-artifacts/view-parity only, outside an isolated candidate checkout.
session.json records the manifest, selected cases, candidate root/commit/dirty
status and file hashes, and
reference source fingerprint. results.json and html/ contain Playwright results.
Each captured case retains reference.png, candidate.png, diff.png and
comparison.json, including viewport, browser version, timestamp, source paths,
available states, active state, URLs, accessibility snapshots and pixel counts.

Both pages use the same browser, viewport, scale 1, en-US locale, UTC timezone,
explicit light/dark theme, motion setting, scene and state. Named-scene captures use
fit=component and the catalog-scene-focus frame without independently resizing
the viewport. Dimension differences fail. Ready AND stable markers, the preview
list/states API, and current slug/state/width/fit must agree. Missing states fail;
interactive fallback pages never count as named states. Two consecutive PNGs must
match before comparison; the harness does not inject CSS or freeze animations.
Animated full-motion cases may need a reviewed deterministic endpoint state.

The checked comparison is exact, including antialiasing: any differing pixel or
accessible snapshot fails. This exposes drift; it does not assert that every
failure is an application bug. Inspect all three images in the report. There is
no auto-blessing command and no --update-snapshots path. Fix the candidate or
review an intentional reference change explicitly. A functional pass alone is
never proof of visual parity. Uncovered surfaces remain in scene-manifest.json.

Isolated candidates while parallel edits continue

--candidate-root defaults to the owning checkout. Set it to the exact Git worktree
root served by --candidate-url; paths inside a checkout are rejected. All candidate
source-pointer checks, session/journey/case hashes and completion hashes use that
root. Evidence still defaults to the owning workspace's .demo-artifacts/view-parity,
not the candidate checkout. Do not use the candidate as an evidence directory.
A dirty candidate is recorded honestly; changing content during a run fails.

Example from the owning workspace (substitute the ready commit):
  git worktree add --detach .demo-artifacts/view-parity/candidate <ready-commit>
  cd .demo-artifacts/view-parity/candidate
  corepack pnpm install --frozen-lockfile --ignore-scripts
  corepack pnpm --filter @intent/react dev --port 5176

Install dependencies in that checkout; shared node_modules symlinks can both
change during a run and put font URLs outside Vite's file-serving allow list.
The renderer predev step generates localization inputs. Native Electron install
scripts are not needed for this browser-only app. In the owning workspace:
  corepack pnpm --filter @intent/view-parity test:core \
    --candidate-root /absolute/path/to/candidate --candidate-url http://127.0.0.1:5176

The same option works for check, parity, extended and test discovery, and the
PARITY_CANDIDATE_ROOT environment variable is equivalent. The harness itself and
its manifest always come from the owning workspace. Source fingerprints do not
attest a running server or inspect installed dependency contents.

Refreshing a separately maintained Svelte reference

The reference must have clean tracked sources at the inspected commit. The
manifest fingerprints source, fixtures, fonts/assets, styles, messages, build
configuration, scripts and dependency inputs. Unrelated commits may advance
HEAD if those inputs are identical. Dirty or changed inputs fail before capture;
inputs are checked again after the run. Candidate content edits during a run also fail.
completion.json retains post-run hashes; each journey attaches its own pre/post
candidate provenance. Catalog-fixture captures require the exact fixture and
renderer IDs, the reviewed rendered-state markers, loaded fonts/images and two
identical PNGs. These markers describe fixture availability, not executed state
coverage. Catalog captures omit state/fit and crop the actual fixture wrapper.
The closed-dialog fixture explicitly dismisses the separately mounted initial
dialog with Escape before capture. Open overlays are not covered by that crop.

  corepack pnpm --filter @intent/view-parity reference:inspect \
    --reference-root /absolute/path/to/current-svelte-checkout

This prints commit, source paths, fingerprint and dirty paths without editing
anything. Review incoming source changes and the live list/states API; update
reference.commit and reference.sourceTreeSha256 in scene-manifest.json by hand,
then update affected cases and source pointers. Restart the reference server
from that checkout and rerun. A reference branch/worktree can track current
Svelte development independently of the React branch.

Provenance limitation: the existing preview API has no server commit endpoint.
Both URL-to-checkout associations are operator-declared, recorded as such, and
cannot be independently proven by this package. Source fingerprints detect
checkout drift; they cannot identify an unrelated stale server at the same URL.
Keep that server attached to the declared checkout and restart it after changes.

Native component journeys

The native core lane also exercises live notification identity/callbacks, actual
clipboard writes, editable headers, recipes, real TipTap node transactions,
QuestionWizard admission and pasted-image FileReader bytes, shared-key panel
preferences after reload, native attachments and image/video metadata/downloads.
Images are encoded PNG files; video is a short MP4 recorded from a real canvas
stream using Chromium MediaRecorder. No media dimensions, duration, preload,
upload completion, backend response, or transport is replaced. Optional native
edges cover undo deadlines, dismiss/collapse draft lifetime, nested Escape focus,
clipboard image decoding, and editor removal/undo and retry/dismissal.

Named repository-card comparisons explicitly crop the production card body via
captureTarget and wait for its real data-preview-status. The surrounding source
example prose differs from the candidate display wrapper and is outside that
crop. These cases prove static display parity only, not live repository transport,
cache, context-menu or rate-limit actions. All registered toast-header and card
states are declared so missing source states still fail; declaration alone is
not a completed capture. Screenshot comparisons remain exact, including edges.

Toast-header captures require the actual front data-sonner-toast surface. Toasts
are fixed outside the scene frame, so a matching empty frame is not toast evidence.
Rear-stack and expanded-details behavior are separate contracts. Comparison metadata
records source and candidate capture rectangles alongside exact image dimensions.
Run native core and extended lanes sequentially: the operating-system clipboard is
shared across browser contexts. Editor undo checks start with a fresh editor rather
than assuming adjacent native transactions create separate history groups. Undoable
notification expiry is an operation callback; source display lifetime may continue
while hovered and is tested separately from that deadline.
